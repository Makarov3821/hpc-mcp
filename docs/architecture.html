一次只看一个使用场景。每一步按“发起请求 → 本地处理 → 远端或持久结果 → 反馈 agent”展开。

已实现：空应用启动与基础集群引导

用户提供连接信息，agent 建立一个可用的 MCP 端点

需要提供什么

agent 类型／数据目录、SSH 别名、LSF 或 Slurm、远程 work_root。免密 SSH 由用户事先配置；未知调度器可先探测。

最终得到什么

可连接的 MCP 端点、保存的 clusters.toml 与 state-dir、探测证据。尚未注册应用时，不能直接准备 Gaussian／VASP。

用户 → agent 安装与配置 → MCP 初始化 → SSH 只读探测 → 保存集群设置
① 用户／agent 发起
② 本地安装／MCP 处理
③ 远端／持久结果
④ 反馈给 agent
用户／agent 发起 STEP 01

提供安装位置与 SSH 信息

本地安装／MCP 处理 agent 通过本地 shell 安装项目和虚拟环境，配置启动命令及绝对 config／state 路径。此时 MCP 还未启动。
远端／持久结果 代码与环境放入 agent 数据目录；用户指定位置时采用显式覆盖。
反馈给 agent 安装位置、启动配置、缺少的依赖；agent 向用户报告。
涉及的模块／接口

README 安装流程；此步由 agent／本地 shell 执行，不是 MCP 工具

用户／agent 发起 STEP 02

agent 启动 MCP，发现工具

本地安装／MCP 处理 stdio 初始化、tools/list、settings_get；加载配置和本地状态。
远端／持久结果 MCP 是本地进程端点，SSH 是对集群的外部通道。
反馈给 agent 可用基础工具、设置字段；Phase 8 初始应用列表为空。
涉及的模块／接口

cli.py → server.py；config.py、history.py；application_list：初始为空

用户／agent 发起 STEP 03

agent 请求 cluster_probe

本地安装／MCP 处理 核对 SSH 身份、调度命令、用户指定目录、队列；可选 module avail。
远端／持久结果 登录入口执行只读查询；不递归扫描软件、不提交验证任务。
反馈给 agent passed／failed／unknown、缺失项、候选调度器与 report_id。
涉及的模块／接口

cluster_probe.py、service.py → ssh.py；schedulers.py 解析队列

用户／agent 发起 STEP 04

用户核对设置，agent 保存

本地安装／MCP 处理 用配置接口保存 SSH 目标、scheduler、work_root 等明确值。
远端／持久结果 clusters.toml 与状态证据持久化；登录检查不是计算节点验证。
反馈给 agent 保存结果、当前集群设置、需要用户补充的项目。
涉及的模块／接口

config.py；cluster_configure／config-set；onboarding_store.py

agent 收到哪些信息

{
  "cluster": "lab",
  "scheduler": "lsf",
  "work_root": "/shared/user/runs",
  "checks": "passed / failed / unknown",
  "next_action": "提供应用脚本并注册"
}

字段概览，非现有工具逐字段响应示例。当前探测和配置接口已有；下一步应用注册属于计划。

异常与分支如何响应

  • SSH 失败：返回诊断，修复连接后重试；不继续提交。
  • 调度器不明确：列出候选，用户选定；不猜。
  • 软件环境信息不足：请求用户脚本或明确路径。

把用户脚本变成持久的应用处理插件

需要提供什么

应用身份（如 gaussian）、适用集群、原提交脚本或 qg16／qvasp 源码、用户希望保留的默认值。

最终得到什么

版本化 handler + manifest + 来源 + 独立审阅报告；用户确认后出现应用工具。真机验证状态单独记录。

用户脚本 → agent 改造与独立审阅循环 → MCP 校验与安装 → 用户确认激活 → 重启发现应用工具
① 用户／agent 发起
② 本地安装／MCP 处理
③ 远端／持久结果
④ 反馈给 agent
用户／agent 发起 STEP 01

用户说明“这是 Gaussian 的脚本”

本地安装／MCP 处理 agent 阅读并生成 handler.py 与 manifest；提交脚本转生成器，复杂处理器保留原生成分支。
远端／持久结果 生成插件草案，不上传任务、不调用原提交器；LLM 只在这一类代码改造环节参与。
反馈给 agent 拟保留的条件、必要差异、未支持功能；agent 展示给用户。
涉及的模块／接口

agent 改造；APPLICATIONS.md 中的 handler v1 契约；此步不是 MCP 自动调用 LLM

用户／agent 发起 STEP 02

agent 调用 application_install

本地安装／MCP 处理 创建受管理暂存，校验 schema、来源哈希、接口与依赖；由 agent 启动全新上下文 reviewer，记录独立审阅结果。
远端／持久结果 草案／版本文件保存在配置数据目录 applications/；失败清理或记录可恢复状态。
反馈给 agent 应用 ID、待确认版本、校验结果、差异与未解析项。
涉及的模块／接口

applications.py 插件管理器；不使用现有 qg16_adapter 硬编码学习

用户／agent 发起 STEP 03

用户确认，agent 调用 application_activate

本地安装／MCP 处理 核对精确版本与确认凭据，原子切换应用／集群默认绑定。
远端／持久结果 确认版本与哈希持久化；MCP 重启后从 manifest 加载 gaussian_prepare 等工具。
反馈给 agent active 版本、工具名、参数 schema、是否需重启；不冒充真机验证通过。
涉及的模块／接口

applications.py 注册表、server.py 工具加载器 → server.py

用户／agent 发起 STEP 04

用户授权一个实际小任务

本地安装／MCP 处理 应用插件准备 → 统一提交／追踪／同步 → 核对实际结果。
远端／持久结果 集群执行；验证证据关联插件版本、参数、环境和输出。
反馈给 agent passed／pending／failed 的验证范围及原始证据。
涉及的模块／接口

任务核心、SSH／rsync 复用；application_validate：稳定日志及标记证据

agent 收到哪些信息

{
  "application": "gaussian",
  "version": 1,
  "registration": "active",
  "validation": "unverified",
  "tool": "gaussian_prepare",
  "restart_required": true
}

反馈字段概览，实际 application_activate 返回完整 application 记录。确认激活与计算节点验证是两个状态。

异常与分支如何响应

  • 未知分支或独立审阅发现差异：保留草案，请 agent／用户补充，不激活。
  • 独立审阅未通过：按意见安装修订版本并再次审阅，不进入用户确认。
  • 工具名冲突、依赖缺失或集群不匹配：返回明确原因。
已实现：注册应用分发、固定 handler 与统一任务核心

MCP 根据已注册应用准备任务，再统一上传提交

需要提供什么

application=gaussian、cluster=lab、A/B/test1.gjf、project_root=A、明确参数覆盖及需要回传的 log／chk。

最终得到什么

每项输入对应独立 run_id 和远程目录；提交后获得 job_id。prepare 与 submit 是两个调用，不等待计算完成。

agent → MCP 应用分发 → handler 子进程 → JobService 快照 → SSH／rsync 提交 → JSON 回执
① 用户／agent 发起
② 本地安装／MCP 处理
③ 远端／持久结果
④ 反馈给 agent
用户／agent 发起 STEP 01

agent 调用 application_prepare 或 gaussian_prepare

本地安装／MCP 处理 匹配应用／集群／调度器与确认版本，校验 manifest 参数 schema。
远端／持久结果 读取注册表；未知应用不执行猜测生成器。
反馈给 agent 未注册：application_not_registered、需要的模板信息；已注册则继续。
涉及的模块／接口

applications.py：应用分发与注册表；server.py 提供工具 schema

用户／agent 发起 STEP 02

agent 提供路径与参数

本地安装／MCP 处理 用 JSON 请求调用固定版本 handler，传入远程 run 目录和本地暂存目录。
远端／持久结果 handler 只生成提交脚本、上传清单、输出映射；不 SSH、不 bsub／sbatch。
反馈给 agent 生成错误明确返回；成功后交任务核心建立准备记录。
涉及的模块／接口

applications.py：handler 子进程：schema、路径、超时、输出大小检查

用户／agent 发起 STEP 03

MCP 保存 prepared 任务

本地安装／MCP 处理 生成输入快照与 SHA 清单，冻结插件版本／参数／脚本、输出规则和目标目录。
远端／持久结果 state-dir 保存记录与快照；原输入不变。独立远程目录为 work_root/run_id。
反馈给 agent run_id、prepared、有效资源、输入规模、输出规则；需要细节调用 job_get。
涉及的模块／接口

jobs.py、history.py；template.application_plugin 版本元数据；responses.py 可复用

用户／agent 发起 STEP 04

agent 审阅并按用户意图调用 job_submit

本地安装／MCP 处理 校验快照，上传并远程校验；保存提交意图，调用正确调度命令。
远端／持久结果 rsync → 独立目录；SSH → bsub 或 sbatch。历史保存 job_id 和原始回执。
反馈给 agent 提交接受／失败／回执不明，run_id、job_id、诊断。接受不等于计算完成。
涉及的模块／接口

jobs.py → transfer.py、ssh.py；job_scheduler.py；history.py

agent 收到哪些信息

{
  "ok": true,
  "run": {
    "run_id": "r_example",
    "phase": "prepared",
    "state": "unknown",
    "remote_dir": "/shared/user/runs/r_example",

    ]
  },

准备回执的精简字段示意。现有准备回执已支持 compact；精简准备回执已包含 plugin 版本与参数。现有 submit／status 返回的 run 可能更完整。

异常与分支如何响应

  • 没有注册 Gaussian：请求用户提供模板，进入场景②。
  • 多版本／集群绑定有歧义：返回候选，不自动选。
  • 提交回执不明：用 job_recover 恢复，禁止盲目重交。
  • 多输入先展开独立 run；授权 workflow 后按并发限制推进，不 packing。
查询、监控、工作流基础能力已有

agent 查询状态；可选协调器在断开连接后继续追踪

需要提供什么

run_id；或明确 monitor_watch 的任务范围、同步选择、重试和清理策略，再启用协调器。

最终得到什么

调度状态、查询是否成功、错误原因及持久通知。排队和运行期间不占住一个工具调用等待完成。

用户／agent 发起 STEP 01

agent 调用 job_status(run_id)

本地安装／MCP 处理 读取已登记身份，核对集群配置，查询实时记录并按需归档回退。
远端／持久结果 LSF：bjobs → bacct／bhist；Slurm：squeue → sacct。
反馈给 agent state、raw_state、exit_code／reason、status_query_ok、查询时间与诊断。
涉及的模块／接口

用户／agent 发起 STEP 02

查询失败或记录暂不可见

本地安装／MCP 处理 保留最后已知状态，返回查询失败／未知证据；不当作已完成。
远端／持久结果 持久历史保留旧观察，当前查询记录失败原因。
反馈给 agent agent 应说明状态未确认，按策略稍后查询；不立即同步为最终结果。
涉及的模块／接口

history.py；jobs.py 状态诊断

用户／agent 发起 STEP 03

agent 明确开启 monitor_watch + monitor_start

本地安装／MCP 处理 协调进程按固定策略轮询，必要时启动同步 worker，写完成／需要注意的事件。
远端／持久结果 coordinator 和 worker 是独立本地进程；监控默认关闭。
反馈给 agent 监控状态、同步 operation_id、通知游标；连接断开后记录仍可保留。
涉及的模块／接口

monitor.py、coordinator.py、monitor_engine.py、operations.py、worker.py

用户／agent 发起 STEP 04

agent 调用 monitor_notifications 或 job_get

本地安装／MCP 处理 读取持久通知／本地任务详情；用游标避免反复展示同一事件。
远端／持久结果 SQLite 中保存任务事件、监控进度与通知；已授权工作流可独立推进。
反馈给 agent 完成、失败、同步冲突、需要用户处理的事项；agent 组织成用户可读回答。
涉及的模块／接口

monitor_notifications；history.py；workflow_engine.py

  "run_id": "r_example",
  "state": "running",
  "raw_state": "RUN",
  "status_query_ok": true,

状态字段概览，实际嵌套在 run 中。状态、同步和应用结果不是同一个字段。这里的反馈以工具响应／通知读取为主，不保证客户端主动推送。

异常与分支如何响应

  • 监控未启用：agent 主动轮询，MCP 不悄悄创建后台服务。
  • 停止协调器不会取消已提交计算；取消需单独 job_cancel。
  • cancel_requested 只是请求事实，最终取消需终止证据。
  • 状态 succeeded 不自动证明科学计算有效；应用结果另查。

异常与分支如何响应

  • 任务仍运行：普通同步标 partial；stable_only 不允许冒充最终输出。

  • 本地结果归位后，远程目录和历史按独立清理策略管理，不随意删除。

卸载反馈字段概览，apply 返回 paths、blockers、status 与 residual_paths。无安装残留指清除受管理文件，不承诺安全擦除，也不删除计算数据。

异常与分支如何响应

  • 存在插件运行／活动任务／版本引用：明确返回占用对象，不暗中取消。
  • 卸载中断：下次恢复完成；残留删除失败有明确原因。
  • MCP 软件自身升级继续走 update_*；这是另一条流程，不等于应用插件更新。

反馈是分阶段的，不是一个“计算完成”布尔值

阶段关键反馈agent 应如何解释
已准备run_id、脚本、资源、输入清单、输出规则、插件版本（计划）可审阅并提交；尚未上传／运行。
已提交job_id、提交回执、是否存在回执不明队列接受了任务；随后查询状态。
运行状态state、原始状态、查询是否成功、时间与原因区分排队、运行、失败、取消和未知；不伪造终态。
已同步实际目录、文件清单与 SHA、complete／partial、错误说明哪些文件已回本地，是否为稳定终态结果。
应用结果终止判据与证据；判据不足则 unknown与调度成功分开；没有应用判据不推断科学正确性。

MCP 返回结构化工具响应。agent 负责把这些信息转述给用户；可选后台进程写持久通知，agent 读取通知后再反馈。日常处理不在 MCP 内部调用 LLM。
