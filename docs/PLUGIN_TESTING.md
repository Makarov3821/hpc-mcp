# 应用插件验收清单

## 离线／协议

使用安装 MCP extra 的环境执行 `PYTHONPATH=src .venv/bin/python -m unittest discover -s tests -v`。测试只使用临时目录和假调度命令；官方 stdio 验证现代／旧版握手、空应用启动、注册、激活、重启后方法与参数 schema、持久任务。

仓库已知示例的开发回归包含：原源码的生成函数 → 原预览产物（仅限已审阅的无提交分支）→ 直接运行 handler → MCP 准备快照。比较文件字节，不只比较某些指令；原 CWD 与 MCP remote_dir 在比较时绑定同一路径。核数／版本／MPI／队列／节点／scratch 等条件覆盖，原来注释掉的逻辑不自行启用。

本仓库的 qg16 256 组、qvasp 576 组已覆盖；这些是仓库开发回归，不作为新用户脚本的注册门槛；新脚本通过独立 reviewer 流程审阅。原 CLI 只在审阅过的测试环境执行，未知预览标志不可盲跑。

## 真机与客户端（需要用户授权）

1. 从无配置／无插件安装开始，检查基础工具可用但没有 gaussian_prepare；只读探测 SSH、调度器、队列、用户工作目录和可选 module avail。
2. 使用用户真实脚本迁移包，调整 clusters、环境路径与队列。install 不执行代码；agent 启动全新上下文 reviewer，提交独立审阅报告；通过后用户确认 activate。
3. 重启 MCP，确认 agent 客户端看到专属方法、条件参数及默认值。未知软件返回 application_not_registered，不执行猜测方案。
4. 在 A/B、A/D 中各准备一个用户许可的小任务，审阅实际脚本、上传清单和输出选择，再提交。确认每个 run 的远程目录独立，身份与历史不丢失。
5. 用 job_status／monitor 查询，再按明确规则回传 log／chk。文件稳定且校验正确后归位；应用验证按 manifest 判据及参数范围记录，不将 DONE 当作科学结果正确。
6. 更新新版本，确认旧快照仍固定原版本；依赖派生任务重新绑定新远程目录。重启后工具 schema 刷新；没有代码与 schema 变化也仍需正确反馈当前加载版本。
7. remove 预览占用。未提交任务可显式 job_cancel 本地放弃；已提交等待实际终态，工作流拥有的任务不能绕过授权机制。apply 删除应用文件，保留输入、输出与历史；重启后专属方法消失。
8. 重复卸载与中断恢复应幂等；cleanup 不越界、不删除系统共享依赖。同步失败、缺文件、权限与实际调度输出不一致须保留诊断。

记录调度器／版本、插件源 SHA、版本、参数、客户端、run_id 与原始错误。真实 Gaussian／VASP 及 Slurm 运行和客户端刷新未执行前保持待验收。LSF 归档与记账等旧功能按站点实际输出另行核对。

## 独立审阅验收

确认工具中不再有 application_check，最小包不需要参考案例。未审阅时激活必须失败；review_request 只提供冻结文件和接口要求，reviewer 不读取改造对话。分别测试 revise、缺项、同会话、非 fresh、pass 带差异／未知项、新版本使用旧 token，均不得激活。按意见安装新版本并重新独立审阅通过后，才请求用户确认。协议测试中的报告是测试夹具，不是真实 LLM 审阅证明。实际客户端必须验证 reviewer 确实在独立上下文中运行。

## Phase 9B 业务门禁

新应用使用 setup_flow_step 的 source/install/review_request/review_submit 和 setup_flow_confirm；原脚本归档后不可替换，revise 必须安装新版本。验证普通受管安装／审阅／激活被拒绝、活动流程引用阻止卸载、过期探测和变化配置阻止确认。中断安装／报告提交后恢复不得产生重复版本或报告。实际客户端独立 reviewer 与计算节点验证仍需真机检查。

## Phase 10A 隔离验收

离线套件需 Linux bubblewrap、libseccomp 与可用 namespace；真实边界测试不 mock 隔离后端。验证只读输入／插件、其他任务与模拟凭据不可读、环境不继承、TCP／Unix socket 和 fork 禁止、内存／总暂存容量／时间／输出限制、符号链接与特殊文件拒绝、依赖变更拒绝、成功／失败副本清理。能力不可用不得运行 handler 或静默降级。trusted 须显式确认并显示权限扩大；SDK stdio 验证工具发现和拒绝无确认配置。原 qg16／qvasp 字节回归及依赖派生同时验证生成行为保持。真机安装先调用 handler_runner_status；远程科学程序仍需另行验证。

## Phase 9C 生命周期验收

`test_lifecycle` 使用离线 LSF／Slurm 命令与真实本地 rsync。覆盖显式批准与启用、CLI 退出后后台提交／归位、重启恢复、多目录输出隔离、上传／同步失败与定向恢复、SSH 丢响应防重交、撤销及扩大权限拒绝、workflow 提交所有权、日志标记通过／失败／缺失、调度失败诊断回传、无判据不冒充通过、清理失败只重试清理、本地输出变化停止。SDK modern／legacy 检查生命周期工具发现与未授权启动拒绝。该套件不证明真实集群软件的科学正确性，真机仍须用用户确认的小任务验收。

## Phase 10B 授权验收

普通脚本／template_run／注册 handler／workflow 都必须精确授权。覆盖未授权零上传、错 token／跨任务授权、完整配置／快照／目录／输出变更、上传中配置变化、撤销后只读恢复不重交、扩大同步／删除范围拒绝、排队 worker token 失效、后台配置重读、监控失效通知。依赖 handoff 生成新 run 后必须暂停，旧 token 不能放行；review 新哈希并确认后再提交。SDK modern／legacy 验证计划／确认工具、未确认提交报错、确认仅持久化且不远程执行。测试确认说明是模拟夹具，不能作为真实用户批准的证明。
